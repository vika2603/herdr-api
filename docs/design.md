# 模块设计

本文档是 `github.com/vika2603/herdr-api` 的架构约定，也是各模块并行开发时的接口契约。所有事实均以 `schema/herdr-api.schema.json`（herdr 0.9.0，协议 22）和 herdr v0.9.0 源码为依据。

## 目标

为 Herdr Socket API 提供 Go 客户端，并为用 Go 编写 Herdr 插件提供运行时辅助。类型和方法封装由生成器从官方 schema 生成，手写代码只覆盖 schema 无法表达的部分：传输层、插件进程环境、少量无判别字段的联合类型。

## 已核实的协议事实

- 传输为本地 socket 上的换行分隔 JSON。Unix 为 Unix domain socket；Windows 为命名管道，`HERDR_SOCKET_PATH` 给出的是文件路径，管道名为 `\\.\pipe\` + 该路径。
- 服务端对每个连接只读取一行请求，写出一行响应后关闭连接（`src/api/server.rs` `handle_connection`）。因此普通调用必须每次新建连接，不能复用或流水线化。
- `events.subscribe` 在返回 `{"type":"subscription_started"}` 后保持连接，之后每行推送一个事件；在该连接上再写入任何数据会导致服务端关闭连接。`pane.graphics.stream` 同样保持连接，但不在 schema 中，本期不生成。
- 推送事件有两种信封，按 `event` 字段区分：
  - 生命周期事件：`{"event":"pane_created","data":{"type":"pane_created",...}}`，`event` 为 `EventKind`（下划线），`data` 按 `type` 判别，对应 schema 的 `event` 段。
  - 三种专用订阅：`{"event":"pane.output_matched","data":{...}}`，`event` 为点号名，`data` 无判别字段，对应 schema 的 `subscription_event` 段。
- 错误响应为 `{"id":"...","error":{"code":"...","message":"..."}}`。请求本身无法解析时 `id` 为空字符串。已观察到的 code 见下文“错误码”。
- 插件事件钩子的 `HERDR_PLUGIN_EVENT` 是点号事件名（`EventKind::dot_name`），`HERDR_PLUGIN_EVENT_JSON` 是完整的 `EventEnvelope` JSON。`HERDR_PLUGIN_CONTEXT_JSON` 是 `PluginInvocationContext` JSON。
- schema 没有记录“方法返回哪个 `ResponseResult` 变体”。该映射由 `schema/method-results.json` 维护，已从 v0.9.0 handler 源码提取。

## 根包 `herdr`：传输层公开接口（冻结）

```go
type Client struct{ /* 私有 */ }
type Option func(*Client)

func New(socketPath string, opts ...Option) *Client          // 不做 I/O
func NewFromEnv(opts ...Option) (*Client, error)             // 见 ResolveSocketPath("")
func ResolveSocketPath(session string) (string, error)
func WithDialTimeout(d time.Duration) Option
func WithRequestIDs(next func() string) Option

func (c *Client) SocketPath() string
func (c *Client) Call(ctx context.Context, method string, params, result any) error
func (c *Client) CallRaw(ctx context.Context, method string, params any) (json.RawMessage, error)
func (c *Client) OpenStream(ctx context.Context, method string, params any) (*Stream, error)

type Stream struct{ /* 私有 */ }
type RawEvent struct {
    Event string          `json:"event"`
    Data  json.RawMessage `json:"data"`
}
func (s *Stream) Ack() json.RawMessage                       // 首行响应的 result 对象
func (s *Stream) Next(ctx context.Context) (*RawEvent, error)
func (s *Stream) Close() error

type Error struct{ Method, Code, Message string }
func (e *Error) Error() string
func IsCode(err error, code string) bool
var ErrStreamClosed error
```

行为要求：

- `Call`/`CallRaw`：新建连接，写入 `{"id","method","params"}` 一行；`params` 为 `nil` 时发送 `{}`；读取一行；`error` 字段存在时返回 `*Error`（携带 `Method`）；否则把 `result` 解码到 `result`（`nil` 则丢弃）。`ctx` 取消或超时通过关闭连接解除阻塞，并返回 `ctx.Err()`。
- `ResolveSocketPath(session)`：`session` 非空时返回 `<config>/sessions/<session>/herdr.sock`；否则依次取 `HERDR_SOCKET_PATH`、`HERDR_SESSION`、默认 `<config>/herdr.sock`。`<config>` 为 `$XDG_CONFIG_HOME/herdr` 或 `~/.config/herdr`；Windows 上以 herdr 源码 `src/server/socket_paths.rs` 为准。
- `OpenStream`：发送请求，读取首行；`error` 时返回 `*Error`；成功时保存 `result` 供 `Ack()` 读取，之后 `Next` 逐行解码为 `RawEvent`。连接关闭后 `Next` 返回 `ErrStreamClosed`（或包装的底层错误）。
- 请求 id 默认形如 `herdr-go-<递增序号>`。
- 传输层不引入第三方依赖。Windows 命名管道用 `os.OpenFile` 打开 `\\.\pipe\` + 路径。

## 根包 `herdr`：生成代码契约

生成器输入：`schema/herdr-api.schema.json` 与 `schema/method-results.json`。输出文件全部位于根包，文件头为 `// Code generated by herdr-apigen. DO NOT EDIT.`：

| 文件 | 内容 |
| --- | --- |
| `schema_gen.go` | `const SchemaProtocol uint32 = 22` |
| `types_gen.go` | 全部 `$defs`（参数、信息结构、枚举、有判别字段的联合类型） |
| `results_gen.go` | `Result` 接口、64 个结果结构、`DecodeResult` |
| `events_gen.go` | `EventKind`、`Event` 接口、事件结构、`DecodeEvent`、`EventEnvelope` |
| `methods_gen.go` | `Method*` 常量与 `(*Client)` 方法封装 |

`generate.go` 含 `//go:generate go run ./cmd/herdr-apigen -schema schema/herdr-api.schema.json -methods schema/method-results.json -out .`。

### 命名规则

- `$defs` 名原样使用（`PaneInfo`、`PluginInvocationContext`）。五个 schema 段中同名定义在把 `$ref` 归一为定义名后必须完全一致，否则生成器报错退出。
- 字段：snake_case 转 PascalCase，首字母缩写词按 Go 惯例大写：`id→ID`、`url→URL`、`json→JSON`、`api→API`、`ttl→TTL`、`pid→PID`、`tty→TTY`、`ansi→ANSI`、`ui→UI`、`cli→CLI`、`os→OS`；其余按单词首字母大写（`cwd→Cwd`、`ms→Ms`、`px→Px`、`data_base64→DataBase64`、`argv0→Argv0`）。
- 枚举：`type AgentStatus string`，常量 `AgentStatusIdle AgentStatus = "idle"`；值中的 `-`、`_`、`.` 都作为单词边界（`recent_unwrapped→RecentUnwrapped`、`top-left→TopLeft`、`antigravity_cli→AntigravityCLI`）。
- `ResponseResult` 变体：`<Pascal(type)>Result`，例如 `pane_info→PaneInfoResult`、`ok→OKResult`、`pong→PongResult`。
- `EventData` 变体：`<Pascal(type)>Event`，例如 `pane_created→PaneCreatedEvent`。与 `subscription_event` 段中 `PaneAgentStatusChangedEvent` 等同名同形的定义合并为一个类型。
- `Subscription` 变体：`<Pascal(type)>Subscription`，点号为单词边界，例如 `pane.agent_status_changed→PaneAgentStatusChangedSubscription`。
- 其他有判别字段的联合类型的变体：`<联合名><Pascal(tag)>`，例如 `LayoutNodePane`、`LayoutNodeSplit`、`PaneMoveDestinationNewTab`、`OutputMatchRegex`、`AgentViewFilterAll`、`EventMatchPaneClosed`。判别字段是每个变体都带 `const` 的那个属性（多为 `type`，`EventMatch` 为 `event`）。
- 方法：`pane.graphics.set→MethodPaneGraphicsSet = "pane.graphics.set"`，封装方法名 `PaneGraphicsSet`。

### 类型映射

| schema | Go |
| --- | --- |
| `string` | `string` |
| `integer` + `format` `uint64`/`uint32`/`uint16`/`int32` | 对应 Go 类型 |
| `integer` + `format` `uint` | `uint64` |
| `integer` 无 format | `int64` |
| `number` | `float64` |
| `boolean` | `bool` |
| `array` | `[]T` |
| `object` + `additionalProperties` | `map[string]T`；值可为 null 时 `map[string]*T` |
| `true`（任意值，如 `agent_explain.explain`） | `json.RawMessage` |
| 有判别字段的 `oneOf`/`anyOf` | 密封接口 + 变体结构（见下） |
| 无判别字段的联合 | 手写类型，见“手写补充” |

可选与可空：

| 情况 | Go 字段 |
| --- | --- |
| required，不可空 | `T` |
| required，可空 | `*T` |
| optional，`string` 或枚举，不可空 | `T` + `omitempty` |
| optional，`bool`/整数/浮点/结构体，不可空 | `*T` + `omitempty`（`strip_ansi` 默认 true，值类型无法表达显式 false） |
| optional，可空 | `*T` + `omitempty`（serde 对 `Option` 字段把 null 与缺失同等处理，因此不需要发送显式 null） |
| optional 数组/映射 | `[]T` / `map[string]T` + `omitempty` |

联合类型的生成形式：

```go
type LayoutNode interface{ isLayoutNode() }
type LayoutNodePane struct{ ... }              // 不含判别字段
func (LayoutNodePane) isLayoutNode() {}
func (v LayoutNodePane) MarshalJSON() ([]byte, error)   // 注入 "type":"pane"
func decodeLayoutNode(data []byte) (LayoutNode, error)  // 读判别字段后解码
```

含联合类型字段（含切片、指针）的结构体生成 `UnmarshalJSON`，先解码到以 `json.RawMessage` 承载联合字段的辅助结构，再逐字段调用 `decodeX`。

### 结果与事件

```go
type Result interface{ ResultType() string }          // 返回 type 常量
func DecodeResult(raw json.RawMessage) (Result, error) // 按 "type" 判别，未知 type 返回 *UnknownResultError

type EventKind string                                  // 下划线名，常量 EventKindPaneCreated
func (k EventKind) DotName() string                    // 首个下划线换为点号，与 herdr EventKind::dot_name 一致
type Event interface{ EventName() string }             // 返回点号名，如 "pane.created"、"pane.output_matched"
type EventEnvelope struct {
    Event EventKind `json:"event"`
    Data  Event     `json:"data"`
}
func DecodeEvent(event string, data json.RawMessage) (Event, error)
func (s *Stream) NextEvent(ctx context.Context) (Event, error)   // Next + DecodeEvent
```

`DecodeEvent`：`event` 含点号时按 `subscription_event` 段的三种事件名直接解码；否则按 `data.type` 解码 `EventData` 变体。未知事件名返回 `*UnknownEventError`，其中保留原始数据。

### 方法封装

由 `method-results.json` 决定形态：

```go
// {"result":"pane_info"}
func (c *Client) PaneGet(ctx context.Context, params PaneTarget) (*PaneInfoResult, error)
// 参数类型为 EmptyParams 或 PingParams 时省略 params
func (c *Client) Ping(ctx context.Context) (*PongResult, error)
// {"results":[...]} 或 "*"
func (c *Client) PluginPaneOpen(ctx context.Context, params PluginPaneOpenParams) (Result, error)
// {"stream":"subscription_started"}
func (c *Client) EventsSubscribe(ctx context.Context, params EventsSubscribeParams) (*Stream, error)
```

单结果封装的实现统一为 `CallRaw` → `DecodeResult` → 类型断言，断言失败返回 `*UnexpectedResultError{Method, Want, Got}`。

### 手写补充（`unions_manual.go`，归 `feat/gen`）

无判别字段的联合由手写类型实现 `MarshalJSON`/`UnmarshalJSON`，生成器通过配置跳过这些定义并直接引用：`PopupSize`（整数或 `"80%"` 字符串）、`AgentViewValue`（string | bool | uint64 | `{"context":...}`）、`AgentViewField` 与 `AgentViewSortField`（内建枚举 | `{"token":...}`）。

### 生成器（`cmd/herdr-apigen`、`internal/gen`）

- 只实现 schema 用到的 JSON Schema 子集：`type`（字符串或数组）、`properties`、`required`、`$ref`、`oneOf`/`anyOf`、`enum`、`const`、`items`、`additionalProperties`、`format`、`description`、`default`。遇到未支持的关键字报错，不静默忽略。
- 输出确定性排序，经 `go/format` 格式化。`description` 写入 godoc。
- 校验：`method-results.json` 必须覆盖 schema 中全部方法，且不得引用不存在的方法或结果类型。
- 测试：命名与映射规则的单元测试；对真实 schema 的黄金输出测试；根包中用 `testdata/` 内从真实服务端捕获的响应做解码往返测试。
- 不引入第三方依赖。

## `plugin` 包

```go
type Env struct {
    PluginID, PluginRoot, ConfigDir, StateDir string
    SocketPath, BinPath                      string
    WorkspaceID, TabID, PaneID               string   // 可为空
    ActionID, EntrypointID                   string   // 按入口类型出现
    Event                                    string   // 点号事件名；startup 钩子为 "startup"
    ContextJSON, EventJSON                   []byte   // 原始 JSON，可为空
    ClickedURL, LinkHandlerID                string
}
func Load() (*Env, error)                 // HERDR_ENV != "1" 或缺少 HERDR_PLUGIN_ID 时报错
func LoadFrom(lookup func(string) (string, bool)) (*Env, error)
func (e *Env) Kind() EntryKind            // Startup | Action | Event | Pane
func (e *Env) Client(opts ...herdr.Option) *herdr.Client
```

阶段二（生成类型合入后）补充：`(e *Env) Context() (*herdr.PluginInvocationContext, error)`、`(e *Env) EventEnvelope() (*herdr.EventEnvelope, error)`，以及按入口分发的 `Run(ctx, Handlers) int`。

## `plugin/manifest` 包

按 `herdr-plugin.toml` 的字段建模并校验：顶层 `id`/`name`/`version`/`min_herdr_version` 必填；`id` 字符集为 ASCII 字母、数字、`.`、`:`、`_`、`-`；局部 id（action、pane、link_handler）不含 `.` 且同类唯一；`platforms` 取值 `linux`/`macos`/`windows`；`command` 为非空 argv；`link_handlers[].action` 必须引用同一插件的 action；`events[].on` 与已知事件点号名比对，未知名给出警告而非错误（与 herdr 行为一致）。TOML 解析可使用 `github.com/BurntSushi/toml`，这是该包唯一允许的第三方依赖。

## 错误码

schema 未枚举错误码。以下取自 herdr v0.9.0 源码，作为 `errors.go` 中的常量提供，同时保留字符串比较能力：
`invalid_request`、`invalid_params`、`internal_error`、`timeout`、`not_found`、`pane_not_found`、`workspace_not_found`、`tab_not_found`、`agent_not_found`、`plugin_not_found`、`plugin_disabled`、`plugin_pane_not_found`、`platform_unsupported`、`feature_disabled`、`ui_busy`、`popup_not_open`、`stream_conflict`、`stream_closed`、`agent_blocked`、`agent_prompt_stalled`、`workspace_group_close_required`、`unsupported_in_app_mode`。

## 版本与兼容

- 生成代码只解码已知字段，忽略未知字段；未知 `type`/`event` 通过 `Unknown*Error` 暴露而不是崩溃。
- 升级 herdr 时替换 `schema/herdr-api.schema.json`、补全 `method-results.json`、重新生成并运行 `just check`。
- 运行时可通过 `Ping` 返回的 `protocol` 与 `SchemaProtocol` 比较，判断服务端是否新于生成代码。
